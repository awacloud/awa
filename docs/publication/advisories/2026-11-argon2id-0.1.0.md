# Argon2id tags of 0.1.0 are not interoperable

Published 2026-11-19 by AwaCloud with the 2026-11-19 release, in the public
monorepo `github.com/awacloud/awa`. Contact: **security@awacloud.com**
(see [`SECURITY.md`](../../../SECURITY.md)).

Severity: low. The WASM crypto tier is an early release (`0.x`). The defect
is an interoperability defect: at realistic parameters a tag computed by
0.1.0 differs from the RFC 9106 Argon2id tag. Found by our own testing; no
external report.

## Affected

- `@awacloud/fw-wasm-crypto` `0.1.0`.
- `@awacloud/fw` `0.1.0`: per fw's CHANGELOG (`### Fixed`, "crypto/wasm"),
  the published package carried none of the 22 `.wasm` binaries of the WASM
  tier (the `files` list left them out), so in an installed package every
  `wasm*` module was unavailable. The pure-JS `argon2` module of
  `@awacloud/fw` `0.1.0` does not share the defect: it reproduces the RFC
  9106 section 5.3 test vector (m = 32, t = 3, p = 4, with secret and
  associated data; segment length 2) and gives the same tag as the fixed
  WASM module on every parameter set measured (m/p in {64/1, 32/4, 8/1,
  64/2}, segment lengths 16, 2, 2, 8).

## What happens

The own Argon2id core started the data-independent address-word cursor at
word 0 in the first segment of pass 0, which begins at block 2; RFC 9106
§3.4.1.2 takes word `i mod 128` for block `i`. Every parameter set whose
segment length (`m / (4·p)`) is 4 or more — every realistic one — produced
a tag that no other Argon2id implementation reproduces. The RFC 9106 §5.3
vector (segment length 2) could not see it.

Separately, `argon2id_hash` returned `-2` for `m ≥ 16384` KiB because the
block matrix came from the shared 16 MiB scratch arena, so the OWASP
parameters could not run.

## Impact

Tags computed by 0.1.0 at a segment length of 4 or more verify only with
0.1.0. A password hash stored from 0.1.0 does not verify with 0.2.0 or with
any other Argon2id implementation.

## Fixed in

`@awacloud/fw-wasm-crypto` `0.2.0` (and `@awacloud/fw` `1.0.0`).

## What to do

Upgrade. Re-hash stored passwords at next login: verify with the 0.1.0
build, store with 0.2.0, since tags cannot be converted.

## On the registry

`@awacloud/fw-wasm-crypto@0.1.0` and `@awacloud/fw@0.1.0` are deprecated on
npm, each message pointing to this advisory.
