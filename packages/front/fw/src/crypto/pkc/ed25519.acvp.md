# `ed25519.js` — ACVP / NIST conformance

## Standards

- **Primary**: **NIST FIPS 186-5** — *Digital Signature Standard
  (DSS)*, **§7** *EdDSA* (Ed25519 algorithm, edwards25519 curve).
- **Secondary**: **RFC 8032** — *Edwards-Curve Digital Signature
  Algorithm (EdDSA)*, **§5.1** Ed25519 ("pure" variant, PureEdDSA).
- **ACVP draft**: `references/NIST/ACVP/src/draft-celi-acvp-eddsa.adoc`

## Implemented algorithm

`ed25519.factory(sha512, bitArray)` exposes the **PureEdDSA
Ed25519** variant (RFC 8032 §5.1): twisted Edwards curve
−x² + y² = 1 − (121665/121666)·x²·y² over GF(2²⁵⁵−19), an
implementation derived from TweetNaCl (16 limbs of 16-bit
Float64Array, extended projective coordinates `(X, Y, Z, T)` with
`x=X/Z, y=Y/Z, T=XY/Z`).

Public API (`Uint8Array` everywhere):

- `keyPair(seed)` → `{ publicKey: 32B, privateKey: 64B = seed||pub }`
  or `false` if seed ≠ 32 bytes.
- `sign(privateKey, message)` → 64-byte signature (R || S); rejects
  privateKey ≠ 64 bytes.
- `verify(publicKey, message, signature)` → `true | false`
  (constant-time comparison: accumulated XOR over 32 bytes, line 348).

Internal API (test-only):

- `_internal.isValidPublicKey(pk)` → `true` iff `pk` deserializes into
  a valid point on edwards25519 (`_unpackneg() === 0`). Used
  for the EDDSA-KeyVer-1.0 coverage. Outside the production contract.

**Iteration E1 (FIPS 140-3 upgrade plan)**: added the
**Ed25519ph** (preHash, RFC 8032 §5.1.1 / FIPS 186-5 §7.6.2) and
**Ed25519ctx** (context bytes, RFC 8032 §5.1) variants:
- `signPh(privateKey, message, ctx?)` / `verifyPh(publicKey, message, signature, ctx?)`
  — applies SHA-512 internally to the message + dom2(F=1, ctx) prefix.
- `signCtx(privateKey, message, ctx)` / `verifyCtx(publicKey, message, signature, ctx)`
  — dom2(F=0, ctx) prefix; ctx required (1..255 bytes — for an empty
  ctx, use the pure Ed25519 path via `sign/verify`).

Not implemented (see *Known limitations*): **Ed448** (distinct curve,
SHAKE-256) — iteration E2 adds `ed448.{keyPair,sign,verify,
signPh,verifyPh}` stubs that return `false + warn NOT-IMPLEMENTED` for
safety by default.

### Security properties tested

- [x] **RFC 8032 determinism** — reproducible byte-exact signature
      on 6 vectors (3 RFC + 3 ACVP); no random input in
      `sign` (nonce derived via `_h(prefix, message)`).
- [x] **Constant-time tag comparison** — `verify` accumulates XOR
      over 32 bytes then tests `diff === 0` (ed25519.js line 347-349).
- [x] **Public validation (point on curve)** — `_unpackneg`
      checks `chk² · den = num` (Edwards curve equation); tested
      via 4 ACVP KeyVer vectors (mix of valid/invalid: non-canonical
      encoding, off-curve point, low-order subgroup).
- [x] **`sign` rejects malformed privateKey** — implicit via
      `privateKey.length !== 64` early return.
- [x] **`verify` rejects malformed pk/sig** — early return false on
      incorrect size (lines 328-329).
- [x] **`verify` rejects tampering** — message + signature altered
      on 5 negative ACVP vectors (documented `reason`:
      `signature_changed`, `message_changed`, etc.).
- [x] **Scalar clamping RFC 8032 §5.1.5** — `d[0] &= 248; d[31]
      &= 127; d[31] |= 64` line 274; indirect proof via byte-exact
      keyPair on 4 different seeds (3 RFC + 1 ACVP).
- [x] **Ed25519ph (preHash)** ✅ **Iteration E1** — implemented.
      `signPh(privateKey, message, ctx?)` / `verifyPh` apply SHA-512
      to the message + dom2(F=1, ctx) prefix per RFC 8032 §5.1.1. 3
      ACVP SigGen vectors + 5 SigVer preHash=True byte-exact + 5
      round-trip tests (incl. domain separation vs pure Ed25519).
- [x] **Ed25519ctx (context bytes)** ✅ **Iteration E1** — implemented.
      `signCtx(privateKey, message, ctx)` / `verifyCtx` apply
      dom2(F=0, ctx) prefix per RFC 8032 §5.1. ctx required (1..255 bytes;
      empty ctx → use pure `sign/verify`). 5 round-trip tests
      (round-trip + wrong-ctx rejection + cross-mode pure rejection + 0/256 bounds).
- [x] **Ed448 — documented decision** ✅ **Iteration E2** — Ed448
      (FIPS 186-5 §7.7, edwards448 curve + SHAKE-256, 57-byte pk,
      114-byte sig) **not implemented by design**. ACVP covers:
      KeyGen 3, KeyVer 4, SigGen 84 (preHash + ctx), SigVer 10 = 101
      total ED-448 vectors. Rather than partially implementing it,
      the module exposes `ed25519.ed448.{keyPair, sign, verify, signPh,
      verifyPh}`, which return `false` + typed
      `console.warn('NOT-IMPLEMENTED')` pointing to FIPS 186-5 §7.7 +
      RFC 8032 §5.2 + a recommendation to create a separate `ed448.js`
      (to be derived directly from RFC 8032 §5.2).
      **Avoids any silent use** by a consumer that would have
      confused the Ed25519/Ed448 variants.
- [ ] **Strict subgroup check (low-order Q rejection)** — `_unpackneg`
      accepts points of order 8 (cofactor). RFC 8032 §5.1.7 v2
      (May 2017) optionally recommends rejecting them but does not
      require it for PureEdDSA. **P3** — could be added via an
      `n·Q == O` test.

## Known limitations

- **No Ed448**: edwards448 curve + SHAKE-256 not implemented.
  **Iteration E2**: `ed25519.ed448.*` guards that return
  `false + warn NOT-IMPLEMENTED` added to prevent any silent use.
  To enable Ed448: create a separate `ed448.js` (the compression
  function differs; no sharing with ed25519.js). Output 57 bytes
  pk + 114 bytes sig. To be implemented directly from RFC 8032 §5.2.
- ~~**No prehash variant (Ed25519ph)**~~ ✅ **Iteration E1** —
  `signPh(sk, message, ctx?)` / `verifyPh` exposed. The module applies
  SHA-512 internally to the message + dom2(F=1, ctx) prefix per RFC 8032
  §5.1.1.
- ~~**No `context` (Ed25519ctx)**~~ ✅ **Iteration E1** —
  `signCtx(sk, message, ctx)` / `verifyCtx` exposed. ctx required (1..255
  bytes); empty ctx → use `sign/verify` (pure Ed25519 path).
- **Cofactored verification**: `_unpackneg` accepts points
  whose order divides 8·n. RFC 8032 §5.1.7 documents that
  PureEdDSA accepts this ambiguity; strict implementations
  (cf. ed25519-dalek strict mode) reject it. Acceptable for
  standard usage, worth noting for cryptanalytically
  sensitive protocols.
- **TweetNaCl implementation**: no demonstrated timing attack but
  not formally constant-time (Float64 arithmetic, carry
  propagation, `_sel25519` constant-time but `_pow2523` uses a
  fixed addition chain).
