- **Secondary**: ACVP — draft-celi-acvp-sha.

## Implemented algorithm

SHA-384 hash (FIPS 180-4 §6.5). Identical to SHA-512 except for the IV (FIPS 180-4
§5.3.4) and the final truncation (`h.slice(0, 12)` → 384 bits = 12 32-bit
words representing 6 64-bit words).

**Architecture (post-upgrade audit Finding 1 resolved)**: `factory(sha512)` →
`{ fn, hash }`. Thin wrapper (~14 useful LOC) over
`sha512._internal.makeSha(_INIT_384, 12)`. **Previously**: this module
duplicated the ~120 LOC of the 64-bit compression function "to
preserve streaming-state independence" — inconsistent with
sha512_224/256, which already apply this reuse pattern. Compression
over 1024-bit blocks, 64-bit operations emulated as 32-bit (high/low)
pairs, inherited from sha512.js.

#### AFT sub-sampling strategy

The SHA2-384 AFT enumerates 1024 messages at lengths `[0..65535]` bits — **892/1024 tests are non-byte-aligned**. Strategy:

- **Regular stride**: tcId 1, 33, 65, …, 993, 1024 (one in 32).
- **Anchors**: `len=0`, `min(len)`, `max(len)=65535`, and the first tcId for each critical short length (1, 7, 9, 13, 100, 511, 1023, 2047 bits).
- **Volume cap**: tests > 32000 bits filtered out (except the `max(len)` anchor).
- **Total integrated**: **24 / 1024 AFT + 1 MCT** out of 1025 tests + **1 LDT (1 GiB) gated behind `CRYPTO_FULL=1`** (see LDT line below).
- **LDT (testGroup 3)**: **Iteration H1** — tcId=1026 (1 GiB of repeated `3d04a3d3c6a52e47`) integrated behind `CRYPTO_FULL=1`.

Non-byte-aligned vectors are decoded via `bitArray.clamp(ui8_to_ba(bytes), bitLen)`.

### Security properties tested

- [x] **80 rounds / 64-bit message schedule** — covered by 24 AFT spread across the length range (the SHA-384 `_block` runs 80 rounds over emulated 64-bit words).
- [x] **Bit-level inputs (non-byte-aligned)** — covered by the anchors at lengths 1, 7, 9, 13, 100, 511, 1023, 2047 bits.
- [x] **FIPS 180-4 §5.1.2 padding** — implicitly validated by the varied lengths (`≥ 896 mod 1024` cases forcing an extra block).
- [x] **Long-chain stability** — standard MCT: 100,000 consecutive hashes (MSG = 1152 bits); any drift deviates `resultsArray[j]`.
- [x] **Streaming = one-shot** — `chunked update matches one-shot`.
- [x] **512→384 truncation** — `digest is 384 bits (12 x 32-bit words)` validates the `slice(0, 12)`.
- [x] **2^53−1-bit limit** — `update` returns `false` + `console.warn` beyond it.
- [ ] **Side-channel resistance** — N/A (no secret input by default; HMAC usage handled by `hmac.js`).

## Known limitations

- ~~**LDT not integrated**~~ — resolved in **H1**: tcId=1026 (1 GiB) runs under `CRYPTO_FULL=1` byte-exact.
- **AFT sub-sampling**: 24/1024 (≈ 2.3%). Choice driven by message size (cap 32000 bits + anchor 65535).
- **"alternate" MCT version** not tested (ACVP provides `"standard"`).
- **64-bit emulation as 32-bit pairs**: inherited SJCL implementation; the bit-rotation operations are purely deterministic (no data-dependent path on the arithmetic side).
