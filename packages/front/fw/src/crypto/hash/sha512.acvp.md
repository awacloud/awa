# `sha512.js` — ACVP / NIST conformance

## Standards

- **Primary**: **FIPS 180-4** — *Secure Hash Standard (SHS)*, §6.4 (SHA-512).
- **Secondary**: ACVP — draft-celi-acvp-sha.
- **ACVP draft**: `references/NIST/ACVP/src/draft-celi-acvp-sha.adoc`
- **Vectors**: `references/NIST/ACVP-Server-1.1.0.42/gen-val/json-files/SHA2-512-1.0/`

## Implemented algorithm

SHA-512 hash (FIPS 180-4 §6.4). 1024-bit block, 80 rounds, 64-bit
operations emulated as 32-bit (high/low) word pairs. Streaming API:
`factory(bitArray, utf8)` → `{ fn, hash }`. Output `bitArray` 16 × 32-bit
words (512 bits). IV (8 × 64-bit) and K (80 × 64-bit) constants frozen at
factory time; `factory().toString()` remains Worker-serializable.

**Iteration A2 (FIPS 140-3 upgrade)**: extraction of a builder
`_makeSha(init, outWords)` exposed via `_internal.makeSha`. Allows
`sha512_224.js` and `sha512_256.js` (FIPS 180-4 §5.3.6, upcoming in
iteration A3) to share the SHA-512 compression function with a distinct
IV and a digest truncated to 7 or 8 words. **No public API change** —
`fn` and `hash` exposed identically.

#### AFT sub-sampling strategy

The SHA2-512 AFT enumerates 1024 messages at lengths `[1720..12144]` bits (all byte-aligned). Strategy:

- **Regular stride**: one in 16 (tcId 1, 17, 33, …, 1009, 1024).
- **Anchors**: `min(len)`, `max(len)`.
- **Total integrated**: **67 / 1024 AFT + 1 MCT** out of 1025 tests from testGroups 1+2.
- **LDT (testGroup 3)**: **Iteration H1** — tcId=1027 (1 GiB of repeated `be1ae93d42721349`) integrated behind `CRYPTO_FULL=1`.

### Security properties tested

- [x] **80 rounds / 64-bit message schedule** — covered by 67 uniformly spread AFT.
- [x] **FIPS 180-4 §5.1.2 padding** — implicitly validated (varied lengths modulo 1024 including the `≥ 896 mod 1024` cases that force an extra block).
- [x] **Long-chain stability (alternate MCT)** — 100,000 consecutive hashes; `INITIAL_SEED_LENGTH = 3032 bits` (379 bytes) then chaining with byte-aligned padding/truncation.
- [x] **Streaming = one-shot** — `chunked update matches one-shot`.
- [x] **512-bit digest size** — `digest is 512 bits (16 x 32-bit words)`.
- [x] **2^53−1-bit limit** — `update` returns `false` + `console.warn` beyond it.
- [ ] **Side-channel resistance** — N/A (no secret input by default; HMAC usage handled by `hmac.js`).
- [x] **Parameterizable IV/outWords builder** (iteration A2) — `_internal.makeSha(init, outWords)`
      tests: SHA-512 reproduction with standard IV; consistent `outWords=8/7`
      truncation (prefix of the full 512-bit digest); IV binding (custom IV → digest ≠);
      preserved HMAC contract on the constructed module; clone constructor + streaming = one-shot
      on the truncated module. **8 dedicated tests** (sha512 suite: 74 → 82 tests).

## Known limitations

- ~~**LDT not integrated**~~ — resolved in **H1**: tcId=1027 (1 GiB) runs under `CRYPTO_FULL=1` byte-exact.
- **AFT sub-sampling**: 67/1024 (≈ 6.5%). The 957 unplayed vectors share the same `_block` code path.
- **"standard" MCT version** not tested (ACVP provides `"alternate"`).
- **No non-byte-aligned case**: unlike SHA-224/SHA-384, the ACVP SHA-512 suite only provides byte-aligned messages. The bit-level code path (partial clamp) nonetheless remains indirectly exercised by the other SHA-2 modules.
