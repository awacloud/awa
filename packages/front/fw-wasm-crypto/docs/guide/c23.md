# C23 posture

Own Tier-A sources are authored to the C23 standard; what that buys and how.

## Scope

The C23 posture applies to all `sourceKind: own` modules:
`chacha20poly1305`, `sha2`, `sha3`, `blake2b`, `cmac`, `hmac`, `hkdf`,
`pbkdf2`, and `argon2`. Vendored and vendored-fork modules use `cStd: c99`
(set explicitly in `targets.json`) or the vendored project's own standard.

## What C23 provides

**Fixed-width types without a compatibility shim.** `<stdint.h>` has been
part of C since C99, but C23 also mandates `_BitInt(N)` and tightens the
signed-integer overflow rules. The own sources use `uint32_t`/`uint64_t`
throughout, with zero UB-reliant sign-extension tricks.

**`static_assert` as a keyword.** C11 introduced `_Static_assert`; C23
promotes `static_assert` to a keyword (no `<assert.h>` needed). The own
sources use it to verify structural invariants at compile time (e.g. that
the Keccak state struct is the right size).

**`constexpr` for compile-time constants.** C23 adds `constexpr` for
typed compile-time constants, replacing `#define` literal macros. The own
sources use `constexpr` for tag sizes, block widths, and output lengths.

**Cleaner `[[nodiscard]]` and attribute syntax.** C23 standardizes
`[[nodiscard]]` and `[[maybe_unused]]` so the sources annotate allocation
and error-return functions without compiler-specific extensions.

## Toolchain pin

The build pins **wasi-sdk-33 / clang-22** (via `tools/wasm-crypto
build-env/`). Clang 22.1 is the first release that supports the full C23
feature set used in `csrc/` (including `constexpr` — confirmed by a real
build; an earlier concern about clang-18 lacking it is superseded). The
builder records the SDK path via
`WASI_SDK_PATH` or `build-env/toolchain.ts` discovery; any other clang
version is unsupported and may reject C23 syntax.

## C standard per target

`targets.json` carries an optional `cStd` field. When the field is absent,
`tools/wasm-crypto` applies the default standard (C23 for `csrc/` and
`shims/` sources, C standard of the vendored project for `vendor/` sources,
as resolved by `cStdFor()` in `build.ts`). All nine `own` modules omit
`cStd` from `targets.json`, confirming the C23 default applies.
