## Why hand-authored rather than vendored

`office/BATCH_26` task 05's own plan (`## Scope §Out`) forbids any new
fixture "requiring licensing review" — every construct these three files
exercise (headings, emphasis, links, lists, tables, front matter, code
fences, blockquotes, thematic breaks, image references, task lists,
column alignment) is generic CommonMark/GFM syntax with no possible
copyright attachment, so hand-authoring directly (rather than sourcing
from a third party) was the correct, and only necessary, choice — the
same reasoning `../odp/PROVENANCE.md` and `../ods/PROVENANCE.md` already
apply to their own first-party generated fixtures, one level further
down (script-generated bytes vs. hand-typed markdown text).

## Content design notes (why each construct is present)

- `md-structural.md` is deliberately the ONE fixture reused across
  multiple legs of `tests/roundtrip.integration.test.js` (construct
  survival through docx, exact-loss-ledger through odt, normal-form
  idempotence through both, the mutation falsification check) — every
  construct the plan's Targets table names for this file is present
  exactly once, so a construct's presence/absence in a round-tripped
  body is unambiguous.
- `md-nested.md`'s two lists are ADJACENT (no separating paragraph) on
  purpose — the plan's own leg 6 measures the write leg's depth
  preservation (`pPr.numPr.ilvl === 1`) and the read leg's documented
  flattening (`list/nesting-flattened`), neither of which needs a
  separator; nothing in leg 6 depends on the two lists NOT touching.
- `md-degrade.md`'s front matter is the profile-v1 input leg's
  "document WITH front matter fed into `fromMd`" case (leg 5); every
  other construct in the file is a documented tier-1/degrade case
  already named by the plan's Targets table for this file.

## A genuine measured finding this corpus surfaced (not a fixture defect)

`md-structural.md`'s one bullet list immediately followed by one ordered
list is NOT idempotent at N1 through the odt target (`tests/
roundtrip.integration.test.js`, leg 2's odt sub-case, measured and
asserted, not hidden): `../../src/write/ir-to-odt.js` (GAP-ODF-6) writes
BOTH lists as indistinguishable generic odt lists, so a second markdown
pass sees two ADJACENT same-marker bullet lists and CommonMark's list-
continuation rule merges them into one. The pipeline stabilises one pass
later (N2 === N3, asserted). This is a genuine second-order consequence
of the already-documented GAP-ODF-6 gap, surfaced by this fixture's
specific (and prescribed) list adjacency — not something this task's
fixture was redesigned to dodge. See the harness file's own header
comment and task 05's report for the full account.
